## Verdicts and root causes

1. **Shell `lcars status`: expected command-not-found, not an installer defect.**
   `README.md` Installation explicitly distinguishes agent skills
   (`lcars <verb>`) from the five real shell programs. `vision.md` makes the same
   distinction in The Kanban Interface. `install.sh` installs exactly
   `lcars-viewscreen`, `lcars-serve`, `lcars-launch`, `lcars-buddy`, and
   `lcars-autopilot`; it does not promise a shell `lcars` dispatcher.
   The isolated installed-bin-only shell probe returned **127**, containing
   `lcars: command not found`, while all five real launcher selftests returned
   **0**. A PATH repair cannot turn an agent skill into a shell command.
   Added explicit status/PATH clarification to README, not a new dispatcher or
   installer behavior. `lcars status` remains available through either agent.

2. **Launch help: actual defect, fixed.** The launch parser treated `--help`
   as an unknown option and `-h` as a mission id. It now handles both as
   successful usage reads before repository/mission resolution. It documents
   mission/main forms, stop, keep-worktree, and literal hints. Existing `--`
   semantics remain intact: help-looking words after it are literal.

3. **Viewscreen: two actual defects, fixed.**
   - `_ai_session` checked `CLAUDECODE=1` first. The current Copilot session
     really has both that inherited marker and `COPILOT_CLI_BINARY_VERSION`.
     Copilot's existing documented markers now take precedence; Claude-only
     detection still works. This changes the diagnostic label, not the refusal.
   - Help traversed the startup/dependency/guard path. In an agent it returned
     the startup refusal instead of usage. It did **not actually start a board**
     in the observed red case: the existing guard stopped it. `-h`/`--help`
     now print shell usage before Python, git, configuration, version checking,
     or startup. `--open --help` is a read too. `lcars-serve` inherits this through
     its existing shim. Actual starts still return **3** for every tested agent
     marker combination and never reach the daemon.

Help conventions inspected: installer and Number One accept `-h`/`--help`
(and bare `help`); autopilot already exposes help; viewscreen's Python
argparse advertises `-h`/`--help`. Launch retains bare words as mission/hint
input rather than stealing a mission named `help`. Buddy's collector does not
have a help dispatcher; no unrelated command rewrite was undertaken.
