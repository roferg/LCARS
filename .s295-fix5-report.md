# S295 fix 5: verification must not occupy the project's test port

## Decision and result

Chosen shape: **stop our app, run the unchanged declared tests, then relaunch
before the browser walk**. Both `evaluate` and `recheck` use this ordering.
The additive `launch --stop --keep-worktree` stops the owned process group but
retains the checkout for tests; ordinary `--stop` still removes it. Test writes
are restored using existing tree aftercare before relaunch. URL and launch
status are read after relaunch, not reused from the first launch. A stop-command
failure aborts before running tests. Without a declared command there is no
extra stop/relaunch.

This works without guessing a project's port or assuming it accepts `PORT`.
The launcher's `url_port`, `url_with_port`, and `listen_ports_of_group`
machinery reconciles the reported URL with an observed listener, including a
server that silently bumps its own port. It does not provide a universal way
to make an arbitrary project's command bind a different port. Reusing launch's
process-group stop is therefore safer than imposing a port override.

The regression starts an actual HTTP server on an OS-selected port, then runs
a declared Python command that requires that same port to be unoccupied and
bindable. Before the fix that command failed because LCARS held the listener.
After the fix it passes, and the actual passing `tests.json` reaches the worker.
The recheck repeats that proof and produces its second grade. No exit code,
test verdict, or scorer rule was overridden to manufacture a passing result.

## Evidence caveat

The supplied replay records 21 unittest tests with one failure, on documented
default port 8900, exit 1. Its `verdict` also explicitly says the exit code was
**not counted against the build on its own**. That file proves the collision,
but does not by itself prove a score deduction solely for exit 1. The generic
real-socket reproduction establishes our ordering defect without blaming the
project or assuming the replay's final grading rationale.

## Deliberately unchanged

- No hardcoded port, command rewriting, port-discovery refactor, or universal
  environment override. External processes occupying the port remain real
  environment failures; only LCARS's own app group is stopped.
- No scorer/test-result relaxation, prior-fix changes, board changes, or
  Implement proof-gate changes.
- No full suite or heavy `lcars-run` suite.
- No installer execution: it writes symlinks outside the permitted directory.
  Tests exercised this checkout's scripts directly.
- No version/changelog bump: this is a detached-HEAD fix, not a PR into main.
  No branch, push, PR, or merge.
- The extra launch/discovery pass is a deliberate correctness cost. Relaunch
  errors still follow normal launch-failure handling rather than grading
  fabricated browser evidence.
