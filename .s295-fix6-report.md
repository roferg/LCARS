# S295 fix 6: test the foundation build before merge

## Chain verified

The supplied replay's `xo/tests.json` records `ran=false`, an empty command,
and `outcome=no-test-command`. Its repo config now contains the unittest
command; that later value does not establish what was present at the earlier
Verify look.

`xo_run_tests` reads repo config at look time, not a snapshot, and previously
had no other command-resolution route. Setup's `greenfield_detect_cmd` calls
the shared `detect_test_cmd`, with `TOPLEVEL` scoped to the build. Setup adopts
that result only for its process. The comment withholding repo-config writes
until merge is intentional: sibling missions must not inherit a runner that
exists only on an unmerged branch. Approve promotes it only after successful
merge. The `--again` comment documents the resulting missing-command escape
hatch. No contradictory pre-Verify route was found.

## Resolution and evidence

When config has no command, `xo_run_tests` now calls the same shared
`detect_test_cmd` already loaded from `lcars-common.sh`, with local `TOPLEVEL`
set to its resolved launched worktree. The existing reach-worktree fallback
remains available. No new detector, configuration writer, or launch plumbing
was introduced.

`tests.json` now carries `commandSource`: `config`, `detected-from-build`, or
null when no source supplied a command. Configured commands retain precedence.
Detection occurs before the existing stop/run/relaunch sequence, so detected
commands also run with the app's port released.

The failing-first B24e regression removes the config key and creates a real
stdlib unittest suite only in the launched build, not the captain's checkout.
Before production edits its record was:

```json
{"ran": false, "command": "", "outcome": "no-test-command", "exitCode": null}
```

After the fix, the shared detector supplied:

```sh
python3 -m unittest discover -s "${LCARS_TESTS_DIR:-tests}"
```

The record says `ran=true`, `commandSource=detected-from-build`,
`outcome=passed`, `exitCode=0`, and includes `BUILD_ONLY_SUITE_RAN`.
A second build-only suite genuinely fails and records `outcome=failed`,
`exitCode=1`, and the unittest failure output; its Verify look still completes.
Both records prove config remained byte-for-byte unchanged. A conflicting
detectable runner does not override a configured command.
