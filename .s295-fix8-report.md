# S295 fix 8: terminal missions do not display live pauses in the CLI

## Decision and changes

The CLI marker is not a deliberate indication of retained pause ownership.
Done is the terminal Stage; there is no further Stage to resume. Recorded
pauses remain authoritative for ownership and become visible again if the
Mission returns to a nonterminal Stage.

Commit `337617a` added the terminal check inside the board's existing shared
JavaScript `runState()` predicate. It did not introduce a cross-language
predicate. The shell renderers use the identical decision: recorded Stage
`done` suppresses live pause presentation.

- Status suppresses the Done row's pause glyph and includes the pause legend
  only when a rendered row actually carries it. The recorded Stage is checked
  before a pending gate can override the displayed Stage.
- Buddy's Mission brief suppresses Done's `⏸ paused` annotation.
- The driver's pause-halt presentation prints the existing shipped/Done halt
  sentence for Done, without a pause glyph or misleading Resume advice.
  Its halt decisions, ordering, emitted events and state writes are unchanged.

Production changes are confined to these three shell renderers. Status and
buddy skill documentation describe the new presentation rule.

## Limits, deviations and teardown

There were two implementation slices and one fresh tester pass, not repeated
fix-loop rounds. No regression was introduced. The tester's initial checksum
probe included driver-created event files and failed; its corrected probe
checked Mission/config state rather than treating expected event appends as
state corruption. The initial failed observation is retained separately.

The path constraint was not perfectly met by delegated work: the driver
implementor reported one absolute-path read, and the first implementor's
initial macOS `mktemp` calls ignored a relative `TMPDIR`, using default system
scratch before explicit templates corrected containment. Subsequent guard
allocations were confined to this worktree. Existing suites and launchers
internally resolve absolute paths after changing directories; explicit
orchestrator paths were relative. These deviations are disclosed, not
claimed as compliance.

The proof drives the actual CLI and real git fixture repositories, not the
captain's live finished Mission records. No fresh headed-browser drive was
needed because this fix does not change web code; web regression suites use
their existing harness and do not establish a new browser proof.

Tester fixtures were removed after the final verdict. Isolated installation,
allocation helpers and temporary fixture roots were removed; evidence logs
remain locally. Pre-existing `.s295-fix5-tmp/` and `.s295-fix7-scratch/` were
preserved.
