# S295 fix 10: tolerate an occupied app port

## Choice and evidence

Chose **tolerance**, not a cleanup rewrite. Before spawning a strict-binding
server, detect an existing TCP listener on the predicted port and suggest an
OS-selected free port through recognized literal command selectors or `PORT`.
Never signal the existing listener. Keep the existing post-spawn process-group
socket observation authoritative: `url` records the actual bound port;
`predictedUrl` retains the original prediction, including path/query/fragment.

Supported selectors: `--port N`, `--port=N`, `-p N`, leading `PORT=N`,
`env PORT=N`, inherited `PORT`, and `python3 -m http.server N`.
Explicit ports that disagree with the prediction are not rewritten, and
unrelated numeric arguments and quoted spaces are preserved.

Read `687421e` before implementation. That change releases an already-running
owned app before declared tests and relaunches it for browser evidence. This
regression instead dies during the app's initial bind, before a usable launch
exists. No changes to that earlier fix or to best-effort verdict/report behavior.

The original traceback does not identify the historical listener's owner.
There is no evidence here establishing that it was foreign-owned, nor that
`687421e` caused or fixes this initial-bind failure. The new foreign listener is
an intentional acceptance fixture, not a claim about tonight's incident.

Lifecycle inspection found existing cleanup on ordinary look completion,
EXIT, TERM/INT stand-down, and the look timeout's TERM path:
`xo_teardown` calls the idempotent `xo_stop_launch`; evaluate and recheck arm
the traps. Relaunch also calls `kill_recorded_launch` for that launch record.
An abandoned look killed with SIGKILL cannot run a trap, and a different
mission's record is not reaped by the next mission. Cleanup cannot safely
reclaim arbitrary listeners, so tolerance is needed independently. No new
cleanup defect was established or speculative cross-mission killing added.

## Deliberately left alone and limits

- XO, approval, status, test-port release, verdict/report handling, process-group
  stopping and worktree retention are unchanged. No refactoring, VERSION bump,
  branch, push, PR or merge.
- This is not a general shell-command rewriter. Shell metacharacters cause
  adaptation to be skipped even inside quoted literal arguments. The tester
  confirmed that quoted dollar/glob/semicolon cases still fail to bind on an
  occupied port; this limitation is documented rather than hidden.
- A quoted-double-quote argument mismatch was also observed on the unoccupied
  baseline, outside the adaptation branch. It was not cured or attributed to
  this patch. No broader command/JSON parsing rewrite was attempted.
- Hard-coded ports ignoring `PORT`, missing inspection/Python tools, and a
  competing bind after port selection remain limitations. No live-model,
  browser or universal-framework compatibility claim; the independent drive
  used `--main`, while the launch suite covers mission launches.
- One implementor round and one fresh tester; no follow-up production fix
  rounds. No regression defects introduced were identified. Two subagents
  were used; token/cost accounting was not exposed, so it is not claimed zero.
  The independent discovery shim recorded 19 calls, zero carrying `--model`;
  no live discovery worker was invoked.
