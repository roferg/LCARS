# S295 fix 13: stored reviewer lifecycle

## Decision

This is **not exclusively historical residue**. A real driver re-entry can
overwrite a completed review today:

1. Verify has `numberOne.status = "finished"` and its recorded evaluation.
2. `cmd_drive` calls `drive_engage_number_one` before checking the PR.
3. That helper previously changed `finished` to `engaged`, replacing the engine
   and engagement timestamp too.
4. GitHub reports the PR merged. `drive_mark_done` records `stage = "done"`
   without changing Number One, leaving the newly corrupted reviewer record.

Re-driving an already-done mission had the same problem, and could even create
a reviewer block where none existed. A newly completed mission can therefore
correctly read `finished` and still be corrupted by a later drive.

The fix is two early returns in `skills/lcars-run/run.sh`: do not engage on an
already-done mission, and do not automatically re-engage an already-finished
reviewer. Existing finished metadata is preserved, not reconstructed.
`skills/lcars-xo/SKILL.md` documents that lifecycle. No display code changed.

**No migration or existing mission-record rewrite was performed.** No completion
path was changed to manufacture `finished`. An abandoned or otherwise incomplete
review remains distinguishable from a finished review. This deliberately does
not promise that every done mission now has a finished reviewer.

## Every ending checked

The lifecycle writers and callers were traced in `skills/lcars-xo/xo.sh`,
`skills/lcars-run/run.sh`, `skills/lcars-run/ownership.sh`,
`skills/lcars-approve/approve.sh`, and `skills/lcars-xo/release-stop.sh`.
Static tracing is distinguished below from executable regression evidence.

| Ending | What it leaves in stored state | Evidence and disposition |
|---|---|---|
| Normal Verify evaluation with a HIGH score | `xo_finish` writes `finished`, score, `evaluatedAt`, and review metadata. | Source trace; existing XO suite exercises high/finished outcomes. Unchanged. |
| Evaluation with LOW/MEDIUM gaps | `xo_finish` deliberately writes `engaged`; filing actual fix missions also records `engaged` and the round. This means the reviewer still has follow-up work, not a completed acceptance. | Source trace and existing XO suite. Not converted to finished merely because a process returned. |
| Evaluation unable to launch the build/browser, unable to decide, or unable to read its verdict | Calls `xo_finish` with LOW/engaged. This is why `evaluatedAt` alone is not a safe completion/migration predicate. Unchanged. |
| Successful recheck, every filed fix held, accept and fold succeeded | Explicitly writes `finished`, `score2`, `recheckedAt`, and last action. | Source trace; existing XO suite exercises accepted rechecks and finality. Unchanged. |
| Recheck blocked by child work, relaunch/browser failure, malformed result, fixes not holding, respond refusal, or blocked fold | `escalate` writes `escalated` and its note; the gate remains the captain's. | Source trace; existing XO suite exercises escalation paths. Unchanged. |

| Explicit stand-down cannot stop the tree | Does not claim `stood-down`; preserves status and records a stop-failed note/event. | Source trace and required XO guard. Unchanged. |
| TERM/INT delivered to a look | `on_stand_down` tears down, preserves a partial report, removes the look PID and releases the claim, but explicitly writes no status. | Declared test-command timeout inside a look | The test runner records `hung`; evaluation can continue to grading. | Abandoned look killed outright, process crash, or reboot before final recording | SIGKILL cannot run traps; no completion status is written. `engaged` and stale PID/claim files can remain. | Approve successfully merges, including its already-merged retry case | Records done/merged and releases owned stop/pause bookkeeping; does not rewrite Number One. A finished reviewer stays finished; an absent/incomplete reviewer is not automatically finished. | Source trace, real approve entry-point controls, 151-assertion approve guard. Approve is not the writer that caused the reproduced downgrade. |
| Approve merge fails | Does not transition to done or complete the reviewer. | Source trace and approve guard. Unchanged. |
| Driver detects GitHub merge while at Verify | Before: initial engagement downgraded finished to engaged, then merge recording left it there. After: finished metadata survives unchanged through done. An incomplete reviewer is still not declared finished. | Failing-first regression through the actual driver and GH merge poll, plus independent fixture drives. Fixed. |
| Paused Verify driver detects a merge | Uses the same done transition. Finished reviewer metadata now survives the initial engagement hook too. | Independent real driver cases for both engines. Fixed by the same guard. |
| Driver invoked again on an already-done mission | Before: could downgrade finished or invent engagement. After: no new engagement, with finished, absent, and abandoned reviewer records preserved. Already-stale legacy records are not rewritten. | Failing-first repeated-drive and no-reviewer cases; independent before/after state comparison. Fixed prospectively. |

The remaining interrupted/incomplete statuses should not be treated as evidence
of a completed review. If the captain wants old records normalized, recommend a
separate, explicitly approved audit/migration with recorded interruption versus
completion semantics. Do not infer completion just from `stage = done`, an
evaluation timestamp, an absent process, or a score. This fix neither needs nor
includes that larger change.

## Failing-first proof

`tests/reviewer-lifecycle.test.sh` drives the actual bash driver and approval
entry points in disposable git repositories. Only the forge, network tools,
notifications, version check, and paid CLIs are stubbed; the stored-state
writers and lifecycle transitions are real.

Before the production change: **30 passed, 4 failed**. The failures were the
finished reviewer downgraded on the merge-detecting drive, the two repeated
already-done drives retaining that corruption, and the already-done mission
without a reviewer gaining one. The merge-detection assertion confirmed the
fixture actually queried the recorded PR.

After the change: **34 passed, 0 failed**, including entire reviewer-object
preservation, a no-reviewer control, an abandoned-review control, approval,
and ordinary active engagement. A final run without any required TMPDIR
environment variable also passed: the new suite works as a standalone suite.

## Fresh tester and regression guard

One implementation round and one fresh tester were used. The tester first
ran the real-entry-point smoke suite: **34/34 assertions passed**. Independent
fixture drives then passed **24/24 cases**, across Claude and Copilot config
choices: **22 driver invocations and 2 approval invocations**. Finished,
already-done, absent-reviewer, abandoned-reviewer, active-engagement, paused
merge, and captain-controlled states were covered.

A spot-check caught two mislabeled independent controls: the initial
stood-down/escalated fixtures actually contained engaged. Their fixture
statuses were corrected and the same independent command rerun:
`python3 tests/lib/cage.py 120 python3 .s295-fix13-scratch/tester/independent.py`.
All **24 cases passed** again, now with actual `stood-down` and `escalated`
states preserved. This was a test-rig correction, not a product fix round.
The tester also corrected compact fixture JSON to the writer's native format
before its first final verdict. No additional product defects were found.

The focused regression and independent drives each counted **0 worker
invocations, 0 model-flag invocations, and 0 network attempts** using PATH
shims. The existing driver-hook suite deliberately invoked its own stub engine
twice, once per engine; these were not real model calls. Orchestrator and
sub-agent token/billing totals are not exposed here; no zero-total-cost claim
is made.

All required regression guards passed. No production lines were removed or
refactored. Existing scratch directories from earlier fixes were left alone;
only this fix's disposable fixtures, isolated install, shims, and logs were
removed after their results were recorded here. The persistent deliverables
are the source guards, skill documentation, regression suite, and this report.
The work is committed on detached HEAD, without a branch, push, PR, or merge.
