# S295 fix 11 — interrupted reports are readable

Preserved partial evidence is now offered explicitly as **INTERRUPTED — partial
report (not a verdict)**. A nonempty full report takes precedence, including
when both files exist. Neither artifact produces an empty report button.
No policy deliberately withholding local partial reports was found.

## Every report-offering surface

| Surface | What it does now |
|---|---|
| Local mission card, including Done cards | Offers **Read the partial report** for partial-only evidence, with an INTERRUPTED/not-a-verdict label and no stale grade. Full reports retain their full-report control and normal score presentation. Neither file means no report button. |
| Mission detail / Number One tab | Opens the selected preserved evidence even without a journal. Partial evidence is labelled and rendered as text, not through the verdict renderer. Existing completed-verdict rendering remains unchanged; a full artifact without verdict metadata is still readable. |
| First Officer's report menu/modal | Offers preserved artifacts in expandable, mission-labelled sections. Partial sections explicitly say INTERRUPTED/not a verdict. Journal history remains separate, and a partial-only mission's journal group does not borrow a stale grade. |
| `GET /api/board` | Supplies the artifact selection as `numberOne.reportKind`: full, partial, or none. Partial-only presentation omits recorded verdict/score fields rather than presenting an unfinished look as a verdict. |
| `GET /api/mission/<id>` | Supplies the selected report text and kind for the Number One tab. Preserved evidence no longer depends on the journal existing. Partial detail contains no fabricated verdict. |
| `GET /api/xo/report` | Uses the CLI's shared reader and includes selected preserved artifacts alongside existing journal/history data. Full wins; neither adds no artifact entry. |
| `lcars xo report [mission]` | Prints the selected artifact, with an explicit interrupted/not-a-verdict heading for partial evidence, followed by the existing journal readout. Both files selects full; neither retains journal-only behavior. |
| Living Number One issue comment | Keeps the full report verbatim when present; otherwise includes the partial verbatim beneath an INTERRUPTED/not-a-verdict heading. Artifact-only records can be rendered without a journal. No GitHub comment was posted during verification. |
| Driver's comment-mirror call path | Already calls the living-comment renderer above, so receives the same selection without changing its invocation timing or driver behavior. |
| Remote-only Done card | Already correctly withholds a local report button it cannot fulfill. Left unchanged; four dedicated regression controls pass, including the local Done control. |

Also inspected `lcars xo status`, `lcars status`, buddy, approve and autopilot.
They offer no additional preserved-report link/reader to wire. Their status
readouts, approve's recorded verdict line, and autopilot's verdict/gate decisions
remain unchanged. In particular, no duplicate partial-reader was added to status
or buddy merely because those directories were mentioned in the symptom.

## Failing-first regression

`InterruptedReportSurfaces.test_report_availability_and_precedence_on_every_read_surface`
uses one table and one expected artifact predicate across partial-only,
full-only, neither, and both. It covers 16 artifact/status combinations:
Verify/engaged, Done/engaged, stood-down, and escalated, with and without a
journal. The same expectation drives HTTP payloads, shipping card/tab/modal
render harnesses, actual CLI output, and actual living-comment output.

Before production edits:

```sh
TMPDIR=.s295-fix11-scratch/tmp PYTHONPATH=web python3 tests/lib/cage.py 120 python3 -m unittest web.tests.test_xo_surfaces.InterruptedReportSurfaces
```

Result: **1 test, 80 behavioral subtest failures, no errors**. For example, the
partial-only card, detail and aggregate endpoint all returned no selected
artifact instead of partial. These were missing-presentation failures, not a
broken runner. A subsequent journal-grade check failed in three cases before
the stale-grade presentation was corrected.

A second failing-first CLI regression covers invalid UTF-8 in a full report
beside a valid partial, invalid partial, neither, and valid full beside invalid
partial. Initially the two unreadable cases falsely succeeded; after the fix
they exit 1 with a path-specific stderr diagnostic and no success report.
An unreadable existing full report never silently downgrades to partial.

## Real evidence and limits

A fresh tester started the shipping read-only daemon against
`.s295-fix11-replay`. Its actual board API contained seven Done missions,
including the supplied partial-only mission, three full-report controls, and
no-artifact controls. The selected partial text exactly matches the supplied
file. Both-precedence controls used isolated downward scratch fixtures.

All **1,098 original replay artifact hashes** matched before and after both
independent drives, including reports, verdicts, journals and mission state.
Only the testers' own daemon processes were stopped.

**Headed-browser proof remains blocked, not passed.** Chrome launched with a
relative profile path forwarded into an existing unrelated browser session
instead of exposing the requested CDP port. Retrying did not produce an owned,
controllable Chrome process. The previous browser rig requires an absolute
profile path; it was not reused because this task forbids absolute paths.
No actual board clicks, modal clicks or screenshot-based visual proof are
claimed. Shipping Node render harnesses and actual HTTP/CLI/comment checks
passed, but they are not substituted for a real browser. Detailed independent
evidence is retained in `.s295-fix11-scratch/tester/` and
`.s295-fix11-scratch/final-tester/`.
