# Fix 7: terminal cards do not render live pause posture

## Decision and scope

Presentation only: `web/static/board.js` returns `idle` from the shared
`runState()` predicate when the mission's stage is `done`. This removes both
the paused/pausing badge and paused dimming, without turning a stale running
flag into a running claim. Nonterminal missions still use the original pause
decision. Historical Number One stood-down text remains.

No state writer, merge path, pause-release ownership rule, or staged replay
record was changed. In particular, `self already-paused` remains owned by its
original pauser, not by the completing mission.

## Challenge check

The card and detail already suppress Done's primary action. The driver has no
stage after Done to advance; a retained pause can make a manually re-invoked
Done driver print its pause halt before reaching its terminal branch, but it
does not prevent useful remaining stage work. Resolve-logs selects active
parents and excludes Done missions. Its separate stop-marker guard is not
changed by hiding this badge. Sending a feature back changes its stage to
Align (a logged bug goes to Plan), where the unchanged pause predicate again
makes the pause visible.

No operation was found that requires showing a live pause badge while the
mission remains Done. Pauses on other missions remain visible and untouched.

## Red first, then green

Done, Implement, and Verify, each paused with both running flag values.
It checks pause labels, dimming, no false running claim, and retained history.
